# Accessibility Requirements

## Interaction

Support keyboard navigation for core workflows, visible focus, logical order and labelled fields. Dialogs manage focus and return it to a meaningful trigger. Editable timeline tasks have a form-based equivalent.

## Meaning

Warnings and quality/solver states include text and do not depend on colour alone. Label units, errors, mandatory fields and disabled-action reasons. Announce important asynchronous completion/failure without excessive screen-reader noise.

## Charts and Tables

Provide textual summaries and accessible tabular values for key chart outcomes. Use headings and proper table semantics. Preserve contrast for interval bands, text and selected states. Support browser zoom without hiding required controls.

## Verification

Review the principal flows manually with keyboard/focus and combine with useful automated checks. Automated success is not complete accessibility proof. Record deficiencies and target browsers; do not claim a standard certification without appropriate assessment.

## Aircraft inspection redesign

The 3D visual is an enhancement to the mapped component list. Use Tab/Enter on named engine buttons to select the same record as a spatial annotation. Overview, Engines, Reset, Zoom in and Zoom out have keyboard controls; no drag is needed to reach quantitative evidence or approval. An unavailable renderer preserves those list actions and an illustrative poster. Camera changes are immediate and no automatic rotation occurs. Reduced-motion CSS removes nonessential transitions.

Use 44px interactive targets, visible focus, semantic token contrast, readable labels beside status markings, a skip link, mobile Radix navigation and the existing exact-proposal dialog focus restoration. Single intervals expose text endpoints; histories have observation/source tables and scenarios have saved-result tables. Unknown sensor units remain unknown. Test desktop, tablet, mobile, 200% browser zoom, reduced motion, keyboard traversal, error/fallback and conflict paths. Verification records actual tested subsets; screen-reader and participant validation remain separate work and no WCAG certification is claimed.
