# Selected security-control verification

Pinned reference: [OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS/tree/v5.0.0/5.0/en). This is a selected-control map, **not an ASVS level assessment or certification**. Deployment is one isolated agency with shared authenticated read access; shared multi-agency mode is rejected. No private operational data or real account was introduced.

| ASVS 5.0.0 control | Implemented boundary and verification | Limitation |
|---|---|---|
| 2.1.1, 2.2.1–2.2.3: validation rules and trusted validation | Canonical finite/chronological FD001 contract, atomic CSV/import adapter, bounded request bodies/configuration and cross-record checks; import/eligibility/API-negative tests. | Real platform schemas/support envelopes remain external. |
| 2.3.3–2.3.4: transactions and limited-resource locking | Stock, crew and bay effects commit with plan/work/audit/outbox; PostgreSQL separate-connection races and direct overlap CHECK/unique rejection. | DB operator privileges are outside API authorization; customer booking semantics must be accepted. |
| 8.1.1, 8.2.1, 8.3.1: documented/server permissions | Engineer/import, planner/calculation, logistics/receipt, supervisor/approval-work and administrator/configuration; forbidden mutations/session/demo-header tests. | Browser visibility is not the control; security review of all routes remains required for operational use. |
| 8.2.2: object access | Single-agency authenticated shared reads; cancellation owner/supervisor check; no artifact upload/download URL from arbitrary client paths. | Fine-grained classified-record policy is not supported or claimed. |
| 8.4.1: cross-tenant protection | Not applicable to supported topology; settings reject multi-agency deployment. | Do not host different agencies in one installation. |
| 7.2.1–7.2.3, 7.4.1–7.4.2: sessions | Backend verification, cryptographic opaque tokens stored as hashes, logout/reset/disabled-account checks; server-session/CSRF/origin/denied-role tests. | Eight-hour absolute expiry; no accepted inactivity/concurrent-session or MFA policy. These broader controls remain pending. |
| 16.5.1, 16.5.4: error handling | Generic exception response with bounded request ID; no payload/secret values in application request errors. | External log access/retention, tamper resistance and incident monitoring require an operator plan. |
| V12 secure communication | Production guard requires Secure cookies/explicit HTTPS origins; reverse proxy/TLS deployment preparation retained. | No trusted public domain/certificate environment has been tested. |

Selected runtime tests deny unauthenticated streams/jobs/resources and production/session customer-trial routes, enforce role/CSRF/origin checks, reject oversized chunked input, preserve resource versions and reject unsupported shared scope. Registered model bytes are hash checked before serving; calibration and transform compatibility/corruption tests fail closed. Model artifacts are trusted administrator/offline artifacts, not arbitrary executable uploads.

Account bootstrap remains `scripts/provision_user.py`; passwords are prompted, not put into command arguments. Production disables demo seeding/authentication and automatic schema creation. The local verification stack deliberately uses labelled demo credentials and loopback-only ports; it is not production configuration. Deployment secrets are excluded from backup metadata and require separately protected retention. Generic request/body bounds and login throttling do not establish a comprehensive abuse/quota defense.

The applicable normative sources are [validation/business logic](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x11-V2-Validation-and-Business-Logic.md), [authorization](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x17-V8-Authorization.md), [session management](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x16-V7-Session-Management.md), and [error/log handling](https://raw.githubusercontent.com/OWASP/ASVS/v5.0.0/5.0/en/0x25-V16-Security-Logging-and-Error-Handling.md). Independent threat modelling, security review and agency deployment approval remain external acceptance work.
